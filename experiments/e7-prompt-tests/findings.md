# E7 findings: prompt size, tests in the loop

*Run 2026-10-10, branch `e7-prompt-tests`.* Two questions in one run. **Prompt size:** does Qwen3-Coder 30B do better on a prompt with the human-facing sections dropped (`reference`, 21.5k tokens, `num_ctx` 32768) than on the whole of chapters 3–10 (`full`, 32.5k tokens, `num_ctx` 65536)? **Tests in the loop:** every task now asks for tests, and a round passes only if `alder check` is clean, `alder build --emit` succeeds and `alder test` passes. Matrix: Qwen3-Coder × {`reference`, `full`} × T2–T6, Haiku and Sonnet × `full` × T2–T6, all `--build --test --retries 2`; 20 cells. Raw data: `{reference,full}/runs/<model>/<task>/`; table: `scores.md` (generated by `report_loop.py`); run log: `RUN.md`. Every number below comes from the `summary.json`s, `check.json`s or `sizes.md` unless it is marked *hand-scored*. A read-only data audit of the run found the data sound; facts it verified are marked *(audit)*.

3. ``app/App.alder:6:51: error[E0002]: unknown constructor `Light` `` (`reference` T3 r0; 61 like it over T3–T6), beside ``app/Layout.alder:3:1: error[E0002]: unknown module `Theme` `` in an app with no `app/Theme.alder`. Nothing says which module was meant or that the file is missing; Qwen added imports of a module it never wrote. **Fix:** E6's "`Light` is a constructor of `Theme.Theme`; import `Theme`" when the module exists; when an `import X` names no file, one error at the import, "there is no `app/Theme.alder`: write the module or remove the import", that suppresses the E0002s it causes.

Also misleading, not quoted: E0002 "`App` has no `update`; …" (`full` T4 r1, r2) for a test in `Notes.Show` that calls `App.update`: `App` does have an `update`, and the message should say a test of it belongs in `app/App.alder`. And E5 problem 2 is unchanged: `module Blog.Post is not imported` with `fix: import Blog.Post`, then "unknown module `Blog.Post`" (`full` T3 r0 → r1).

## 6. Harness notes

- **T2 runaway (Qwen, both conditions); the deviation is in §0.** It is a design signal about the task wording. E6's Qwen T2 round 0 was 1,743 tokens with 6 file sections; in E7 both capped round 0s hit 8,192 tokens. `full` wrote 18 sections: the example's files, then `static/app.css` ×3 and `adapters/password.go` (rejected), then `Todos/Index`, `Todos/Show`, `User` and `Profile` again, ending inside a repeated `Todos/Show.alder`. `reference` wrote 56 sections, about 24 of them distinct invented `stdlib/<Module>.alder` stubs (chapter 9's signatures as modules) *(audit)*; they end in `.alder`, so the harness accepted them (it prefixes `app/`), and they account for ~170 of the 194 errors (E0001, E0017 "module `Db` is a standard-library module; rename it", E0005). The go.mod/Dockerfile/linter list is from the uncapped streamed diagnostic of the `full` request, not from a scored round. T2 is the only task that says "Output every file you add or change" (the others say "Output every file"), and the only one whose base app is printed in full in the prompt. Claude read it as intended.
- **The overlay keeps a cut-off file.** Round N+1 starts from round N's files overlaid with what the model re-emits, so a file cut off mid-way persists unless re-emitted: `full` T2's half `Todos/Show.alder` ("expected an expression, got end of file") and `reference` T2's stub modules stayed through both retries (194 → 194 → 194; 5 → 5 → 5).
- **Truncated retry prompts in `reference`.** `reference` T2 r1 and r2 warned that the prompt may have been truncated: Ollama evaluated exactly 16,386 tokens (half the window, 2^14 + 2) against ~31.8k estimated, because the retry prompt carries the previous files in full, and here those were the whole re-emitted app plus the stubs. 16,386 is less than the system prompt alone (21,527), so those retries did not see the whole book *(audit)*. That is a limitation of the `reference` condition as run: a 32k window holds the prompt and an ordinary answer (largest T3–T6 round 30,809), not a retry of a large one. No `full` round warned at 65,536.
- **Wall-clock** (`RUN.md`): Claude 10 runs in 18 min 33 s; Qwen `reference` T3–T6 15 min 14 s, `full` T3–T6 20 min 50 s; capped T2 6 min 35 s and 8 min 23 s; about 2 h 20 min lost to the uncapped T2 attempts. Claude and Qwen overlapped from 13:14 to 13:33, while Qwen ran only `reference` T2 attempt 1; no scored Qwen round overlapped anything.
- **Compiler bugs, model errors:** none. No `test`-kind `compiler_bug`; no "is not wired in tests" (no test called `Password`). Each Claude cell ran once (`claude_version` 2.1.295; the model field is the CLI alias).
- **Rejected paths:** `adapters/password.go` in Haiku T3 r0, Sonnet T5 r0, Sonnet T6 r0 and Qwen `full` T2 r0; `static/app.css` in Qwen `full` T2 r0 (×3) and T5 r0. In Haiku T3 the rejection notice came before the plaintext password (§5).

## 7. What changes because of this

For the controller; nothing here was changed during the experiment.

1. **An agent-facing prompt mode is not the lever for Qwen.** A third less prompt (21.5k vs 32.5k tokens) changed nothing measurable: 0 / 5 both, round-0 errors 40 vs 30, the same error classes, nothing traceable to a dropped section (§2). Keep `--reference` as a harness option (it is how Qwen fits 32k), but do not cut chapters 6–10 for agents on this evidence; Claude passed 10 / 10 on the full prompt.
2. **The example's `Theme` should not be load-bearing.** It accounts for 105 of Qwen's 248 T3–T6 errors and three of Claude's four retries (§2, §5). In order of preference: (a) let a session literal omit fields that have defaults, or give tests a `Test.session { user: me }` that fills them, so a test does not name `theme` (a language change; needs its own decision); (b) move the theme switch out of the example's skeleton (`App`'s session, every page's `Layout` call) into chapter 6's section on app-level messages, so a copied `App.alder` has no `Theme`; (c) at least list `Theme` among the tasks' "modules as in the reference". The diagnostic fix (message 3, §5) is needed whichever is chosen.
3. **Message fixes, each with a corpus case recording today's output** (§5): never offer to import the current module; never offer an import that closes a cycle, and say where the test belongs; report a missing module file once, at the `import`. Also: `if` without `else` in markup ("`if` always has an `else`; in markup write `else Html.none`"; Qwen T6, 30 errors over both conditions, ignored twice in `full`) and "`App.update` can be called only from `App`". E5's problems 2 (a table in another table's module) and 5 (a parse error hides the rest) are still open and cost Qwen again in T3, T4 and T6.
4. **Mixed-brand arithmetic.** Decide whether `Int.NonNegative * Int.Positive` is an `Int` (chapter 4's rules 1 and 3 read together) or an error (the checker), and make the other agree. Both Claude T6 apps multiply through plain `Int`s (Sonnet with an identity function), consistent with avoiding it.
5. **Task wording and the overlay.** Change T2's "Output every file you add or change" to "Output only the files you add or change; not the files you leave as they are, not the standard library, nothing outside `app/`". In the harness, reject `app/stdlib/…`, and for a round that was cut off, drop the cut-off file from the overlay or name it in the retry prompt as a file to re-emit.
6. **Accept `adapters/*.go`, or tell the model the adapter exists.** E6 proposed it; E7 shows a cost of not doing it: the rejection notice came just before Haiku replaced the capability with a plaintext password (§5). At minimum the retry prompt should say "the `Password` adapter is provided; keep the capability".
7. **`qwen3-coder:30b` in the matrix.** At 0 / 10 it no longer discriminates: no Qwen program reached the build or the tests, so it says nothing about either. Keep it for one more run only after items 2 and 3 land (they remove most of its errors without cutting the book); otherwise replace it with a dense 14B–32B coder model, the likelier test of "a small local model writes Alder", or add a smaller book (chapters 3–6 + example) as a separate condition. A different prompt shape alone is not indicated (item 1).
8. **Tests in the loop: keep it, and make the tests hidden in E8.** The models wrote the named tests (28 / 28) and the tests discriminate (10 / 10 mutants), but the loop caught nothing because the programs were already right, and a model's own tests check only what the model thought of. E8's hidden acceptance tests (tasks that pin names, tests run by the harness) are what can fail a program its author believes is right. The tests paragraph also costs a weak model: it is where Qwen's T4 failed and where 39% of its errors sit, so E8 should keep a condition without it.
9. **Row ownership (chapter 12's open question).** T6 is the first task whose authorization the example does not spell out (a role that widens what `load` may show), and both Claude apps got it right first try (Haiku re-checks it in `update`; Sonnet's messages carry no order id and act on the order `load` authorized) and wrote tests that catch its removal. That weakens the case for a language-level ownership helper for strong models; it says nothing about weaker ones (Qwen never got that far).
