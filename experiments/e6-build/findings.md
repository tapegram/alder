## 0. What changed since E5

**Book commit:** `3415cf8` (`git rev-parse --short HEAD` when `prompt.md` was built and the matrix ran).

**Compiler:** the `alder` binary was built from a clean export of `3415cf8` (`git archive HEAD`), not from the working tree: another implementer had uncommitted changes in `cmd/`, `rt/` and `internal/` during the run. `alder build --emit` vets the generated Go against the `rt/` of the tree the binary was built from (`replace alder => …` in the generated `go.mod`), so every build in this experiment used `3415cf8`'s runtime. The binary is `e6-build/alder` (git-ignored). That export was a temporary directory: every generated `go.mod` under `runs/**/round<N>/build/` (git-ignored) says `replace alder => /private/tmp/claude-501/…/scratchpad/alder-head`, a session scratchpad that will not survive, so to vet one of those directories again, point its `replace` at a checkout of `3415cf8`.

**Prompt:** `prompt.md` is 91,729 characters, against E5's 44,941 (`diff e5-loop/prompt.md e6-build/prompt.md`: 1,076 lines added, 68 removed). Same chapters (3–10) and same example app; the book grew in M3a–M3c. New sections, by heading:

- Ch. 3: `## Names`, `## Int`, `## Whitespace`.
- Ch. 6: ``## Authorize in `update` too`` (the section T5 probes), and `## How a request runs` with eight subsections (router, one handler per message, page parameters in the message URL, session cookie, form errors, with and without JavaScript, app messages, failure pages).
- Ch. 7: `## How effects run`, `## Implementing a capability`.
- Ch. 8: `## Migrations` became `## How tables are stored` and `## Schema changes`.
- Ch. 9: `## Form` removed (`Form.values` was dropped in M3c).

The example app changed in two places, both for authorization: `Todos/Index.alder` gained the `owned` helper (`Db.get`, then `Task.notFound` unless `todo.owner == session.user`) and calls it before `Db.update`/`Db.delete` in `Toggle` and `Delete`; `Todos/Show.alder`'s `Save` and `Delete` no longer carry an id and act on `model.todo`, which `load` has authorized.

**Prompt size against Qwen's window:** the system prompt alone is 25,026 tokens by Ollama's count (measured once before the run and not recorded in any tracked artifact; `len/4` estimates 22,917). The harness runs Qwen at `num_ctx` 32768. The largest round (prompt plus output) was 30,842 tokens (`ollama-qwen3-coder-30b/t3-newapp/round1`: `prompt_eval_count` 28,669 + `eval_count` 2,173), 94% of the window. No round got a truncation warning.

**Tasks:** T2–T4 are byte-identical copies of E5's. T5 is new (`tasks/t5-ownership.md`).

## 2. What `--build` found

**Nothing: every program that checked clean also lowered to Go that vets (10 / 10); adapters and linking were not exercised.** Ten runs passed; in each, the passing round ran `alder build --emit` and it exited 0 (`build.exit` of the last round in the ten passing `summary.json`s). No round has a `build.stderr.txt` and no summary has `compiler_bug`, so there is no `repros/` directory. This is the M3 acceptance criterion read in reverse: on ten model-written apps (7–9 modules; 221–336 lines for the new apps of T3–T5, the 8-module example plus a page for T2), none of which the compiler's authors had seen, "type-checks" implied "lowers to Go that vets".

What `--emit` does not cover: it vets the generated package, but does not compile adapters or link an executable, so "built" in this experiment means "vets", not "links". (After the run, the final review linked the ten passing apps with `alder build`, and the fix wave repeated it: 9 of 10 link, with the example's `adapters/` where the app declares the example's `Password` capability and with none where it declares no capability (Haiku's T3); Haiku's T5 declares `verify` returning `Bool` where the example's adapter returns `Maybe`, so it needs its own adapter. A probe, not part of the measurement.) T5 (and T2's base app) declare a `Password` capability; no run had to implement it. Haiku's T5 round 0 *did* emit `adapters/password.go` and `static/app.css`, which the harness refused (`rejected` in that round; only `app/*.alder` is accepted). Qwen's T2 round 0 emitted `static/app.css`, also refused. Models expect to write the Go side of a capability; an experiment that builds the executable should accept `adapters/*.go`.

Classification (as in E5): (a) fixed what was named but introduced a new error; (b) ignored a diagnostic; (c) the compiler's message or fix misled; (d) the compiler was wrong. **There was no (d)**: every reported error is a real mistake by the book.

**One-round fixes, where the message led straight to the fix:**
- *qwen T2* (1 → 0): `app/Profile/Show.alder:24:25: error[E0003]: expected User, got Maybe User; match it: match m { Just x -> …, Nothing -> … }`. The same `Maybe` habit and the same one-retry fix as E5.
- *qwen T4* (1 → 0): ``app/Notes/Show.alder:6:26: error[E0202]: type `NoteId` belongs to module `Note`; write `Note.NoteId` ``, with a fix, applied verbatim.
- *Haiku T5* (5 → 0): a trailing comma after the last expression of a block, twice in `Auth/Login.alder` (`if ok then signIn … else Task.succeed (Reject …),` and `remember id,`). Five `E0001`s, e.g. ``app/Auth/Login.alder:30:96: error[E0001]: in the definition of `update`: expected `}`, got `,` ``. Round 1 deleted exactly the two commas; nothing else changed. Two of the five are a same-span duplicate at 43:6 (E5's "collapse same-span cascades" is still open). A better message would name the rule: "the last expression of a block is its result and takes no `,`".
- *Sonnet T3* (1 → 0): `app/Admin/Index.alder:55:36: error[E0003]: expected Maybe User.UserId, got User.UserId`, at `<Layout.Page title="Admin" user={session.user}>` on a `requires user` page. Round 1 changed only that, to `user={Just session.user}`. The opposite direction (`expected User, got Maybe User`) already says "match it"; this direction could say "wrap it: `Just session.user`" and give the fix.

**qwen3-coder T3 (19 → 4 → 4, fail): (c) misled by E5 problem 2, still open; (b) ignored two messages.**
- Round 0's 19 are mostly one mistake: `Post.alder` declares both `type Post = { … }` / `type Comment = { … }` and `table Post` / `table Comment` (2 × E0009), and the duplicate types cascade into 6 E0003s in `Posts/Admin.alder` (``Db.insert` needs a concrete table``, `expected Id _, got Post.PostId`, `record update on a non-record _`, …). Also a missing `import Theme` (1 E0201 + 3 E0002, see T5) and `Date.format` on a `Time` (2 × E0003). Round 1 removed the record types, imported `Theme` and used `Time.format`, and 18 of the 19 were gone; its 4 are the surviving E0304 (below) and three not reported in round 0: the E0011 below (the `Comment` table's `@id`) and an E0008 in a test, both already in round 0's files, and the `Post.Comment` E0201 that round 1's own edit introduced.
- **(c) misled:** `Comment` is a table declared in module `Post`. Round 0 said ``app/Posts/Show.alder:8:43: error[E0202]: type `Comment` belongs to module `Post`; write `Post.Comment` `` (with that fix), and ``E0201 module `Comment` is not imported`` (`fix: import Comment`). Qwen applied the first. Rounds 1 and 2 then both report ``app/Posts/Show.alder:15:57: error[E0201]: module `Post.Comment` is not imported`` with `fix: import Post.Comment`, at `Db.where (Post.Comment.postId.eq post.id)`. There is no module `Post.Comment`, and a column of a table declared in another table's module cannot be named at all. This is E5 problem 2 unchanged (recorded by this experiment as the new corpus case `E0201-table-in-other-module`), and it cost both retries. A better message, at the declaration: "a table is declared in its own module; move `table Comment` to `app/Comment.alder`".
- **(b) ignored:** ``app/Post.alder:19:3: error[E0011]: `@id` field must be a `brand Text`, got `Text` `` (rounds 1 and 2; no fix offered; existing corpus case `E0011-id-text`). A fix that declares `type CommentId = brand Text` and uses it would remove the guess.
- **(b) ignored, then worse:** ``app/Posts/Admin.alder:58:50: error[E0304]: `<Input>` has no attribute `type` `` at `<Input field="published" label="Published" type="checkbox" />` (rounds 1 and 2). Round 2 kept `type` and added `checked={model.posts == []}` (a second E0304). Chapter 5's table says a `Bool` field renders as a checkbox, but the message does not. Better: "`<Input>` takes its control from the field's type (`published: Bool` is a checkbox); remove `type`" (corpus case `E0304-input-type-attr`).
- Round 2 also replaced a failing test body (`Post { … } != ()`, E0008 in round 1) with `True`. The checker cannot tell a vacuous test; noted as a design signal.

**qwen3-coder T5 (1 → 7 → 4, fail): a parse error hid seven errors (E5 problem 5, still open); then (c) misled by E5 problem 3.**
- Round 0: one diagnostic, ``app/Note.alder:16:3: error[E0602]: `let ... in` is not Alder; use a block: `{ let y = 1 … y }` `` in a test. Round 1 fixed exactly that (the only changed file is `Note.alder`), and the count rose to 7: an E0201 and 3 E0002s for a missing `import Theme` in `App.alder`, and 3 unqualified `NoteId`s (E0202). All of them were in round 0's files, hidden behind the parse error.
- Round 1's ``app/App.alder:6:51: error[E0002]: unknown constructor `Light` `` (three times, no fix) sat next to ``E0201 module `Theme` is not imported`` (`fix: import Theme`). Round 2 added `import Theme`, and also qualified four constructors as `Theme.Light`/`Theme.Dark`: the two `Light`s in `App.alder`'s error and not-found pages and both `Dark`s in `Layout.alder`, which imported `Theme` and had been clean (the session default `theme: Theme = Light` and `Theme.alder` itself stayed bare). Result: 4 × ``E0203 constructors are not qualified; write `Light` `` (`App.alder:28`, `:35`; `Layout.alder:7`, `:15`). The E0002 gave no reason, so the model guessed qualification (corpus case `E0002-ctor-module-not-imported`). Better: "`Light` is a constructor of `Theme.Theme`; import `Theme`", or no E0002 once the E0201 for that module is reported. All four round-2 errors carry a fix, so a third retry would likely have passed; that is a guess, not a measurement.

## 4. T5: does the model authorize `update`?

The `owner-check` column is **hand-scored**: does `update` check ownership before `Db.update`/`Db.delete`? Scored on every passing run, and recorded for the failing one because its code is readable.

**No model forgot to authorize `update` in T5.** Sonnet's and Qwen's `owned` are the example's (`examples/todos/app/Todos/Index.alder`) up to renaming `Todo` to `Note`; Haiku moved it into `Note.alder` as `ownedBy`, with a comment paraphrasing the book.

**The same mistake in T4, before and after** (*hand-scored*; T4 does not mention `update`, only "a user cannot see another user's note"). In E5, two of three T4 apps had the hole the M3c review found in the example: `Notes/Show`'s `load` checked the owner, but `msg Save { id: Note.NoteId }` and `msg Delete { id: Note.NoteId }` updated and deleted `p.id` unchecked (`e5-loop/runs/claude-sonnet/t4-appmsg/round0/app/Notes/Show.alder:24–34`, `e5-loop/runs/ollama-qwen3-coder-30b/t4-appmsg/round0/app/Notes/Show.alder:24–34`, and Qwen's `Notes/Index.alder:26,35`); Haiku's E5 T4 already used id-less messages. In E6, all three T4 apps use id-less `Save`/`Delete` acting on `model.note.id` (`claude-haiku/t4-appmsg/round0/app/Notes/Show.alder:26–36`, `claude-sonnet/t4-appmsg/round0/app/Notes/Show.alder:24–34`, `ollama-qwen3-coder-30b/t4-appmsg/round1/app/Notes/Show.alder:24–34`). E5 → E6: 2 of 3 apps open → 0 of 3, one sample each.

So the models make this mistake when the example makes it (E5), and stop when the example, now backed by chapter 6's "Authorize in `update` too", shows the fix (E6). Both changed between E5 and E6, so E6 cannot separate the two. What E6 does not show is that agents authorize `update` when the example does not spell out the answer: T5 has the example's shape (a list with delete-by-id, a show page by id), and the models copied the example's code. A probe that discriminates needs a message whose authorization the example does not show (§6).

## 6. What changes because of this

For the controller; nothing here was changed during the experiment.

1. **Compiler (next milestone): three of E5's open problems account for both of Qwen's failures.** E5 problem 2 (a table in another table's module; the impossible `import Post.Comment` fix) cost both of Qwen's T3 retries. E5 problem 5 (a parse error hides the rest) hid seven errors in Qwen's T5 round 0, and E5 problem 3 (an unknown constructor with no reason) misled its round 2 (§3). Re-checking E5's repros (`e5-loop/repros/problem-*`) with this binary: problem 4 is fixed (``in a form field: attributes such as `@unique` are only allowed on table fields``; ``in a type: `brand` is only allowed as the whole body of a `type` declaration``); problem 3's ``has type `_` `` cascade is gone but its three E0002s remain; problems 1 and 2 are unchanged.
2. **Message fixes, each with a corpus case recording today's output** (`testdata/corpus/<case>/expected.diag` is the current message; the fix rewrites it):
   - `E0002-ctor-module-not-imported`: "`Light` is a constructor of `Theme.Theme`; import `Theme`" (Qwen T5 r1 → r2).
   - `E0201-table-in-other-module`: an error at the declaration; never offer `import Post.Comment` (Qwen T3 r1, r2).
   - `E0304-input-type-attr`: say the control comes from the field's type (Qwen T3 r1, r2).
   - Without a new case: `E0011` on an `@id` of type `Text` should offer the `type XId = brand Text` fix (existing `E0011-id-text`); E0003 "expected Maybe T, got T" should offer `Just` (Sonnet T3); a trailing `,` after a block's last expression should get its own E0001 reason, and same-span E0001 duplicates should collapse (Haiku T5).
3. **Book: no change measured.** The "Authorize in `update` too" section and the example's `owned` reach all three models (§4). No run failed for lack of a rule in the book; every failure traces to a message (above). Chapter 5's `<Input>` table already says `Bool` is a checkbox.
4. **Chapter 12's open question on row ownership stays open, with a better probe.** E5 → E6 shows that the example, now backed by chapter 6, decides whether apps have the hole; E6 cannot separate the two (§4). To learn whether a language-level helper is needed, run a T5 variant whose authorization the example does not spell out: an `Edit { id }` message with a form on the list page, or a second owned table reached through the first (comments on a note, deleted by comment id, owned through the note).
5. **The prompt is near Qwen's window:** 30,842 of 32,768 tokens at the largest round (§0). The next growth of chapters 3–10 will truncate Qwen's retries. Before E7, raise `num_ctx` in `run_loop.py` (memory permitting) or cut the prompt (e.g. drop "How a request runs", which no task needs).
6. **Experiment design:** at about 10 minutes per matrix, run each Claude cell several times and give Qwen `--retries 3` or more; every Claude retry in E6 is one sample.
