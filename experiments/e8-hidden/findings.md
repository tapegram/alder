## 0. What changed since E7

**Material** (Task 1, `experiments/e8-hidden/`). Five tasks, each with a **Names** block that fixes every identifier a hidden test uses: page modules, paths and parameters; forms and fields; messages; `App`'s session verbatim; redirects; the tables verbatim with "add no further fields"; an `id`/`class` per element a test reads. T4–T6 are E7's tasks with the block. T7 (drafts) changes `base/blog-nodrafts` (the blog with drafts taken out) and is a schema change. T8 (notify) changes `examples/blog` and adds a fixed `Mailer` capability with a fixed `fake`. Two conditions: `with` (E7's tests paragraph) and `without` (the same text minus that paragraph; `verify.sh` checks the texts differ only there and that `without` never says "test"). One hidden module per task (`hidden/<task>/Hidden.alder`, 8 + 8 + 9 + 7 + 5 = 37 tests), browser-only (`Test.login`, `Test.get`/`open`/`submit`/`click`, `Doc` queries, `Db` rows, `Test.fake Mailer`), gated on two different reference solutions per task and on hand-made mutants (README "Verify").

**The stale-page tests** (Task 1, fix round). A test outside the page module cannot build a forged request (E0002), so the hidden tests hold a page as its owner saw it, change what the server knows, then click: the cookie swapped to a stranger's (T5 Delete, T7 Publish), or the row changed underneath (T5 a note deleted meanwhile, T6 an order paid meanwhile). Each catches its mutant (T5 Delete without the owner check 7/8; T7 Publish without it 6/7; T6 AddLine without the Open check 8/9).

**Harness** (Task 2). `--hidden DIR` runs the hidden module on a scratch copy of the final round once it checked clean and built, whether its own tests passed or not; a hidden module that does not compile fails every hidden test with the first diagnostic. `--condition` and `--sample` label the run; `report_loop.py` takes several directories and adds `Condition` and `Hidden` columns. **The base in the prompt:** with `--base`, round 0's prompt now carries the base app's `app/**/*.alder` under "THE APP YOU ARE CHANGING" (E7's T2 prompt was the task alone, and the book never shows the blog). So T7 and T8 models see the blog's code, its tests included.

**Prompts** (`sizes.md`). The book grew with M5 (chapter 10's browser, chapter 8's migrations, fakes): `full` is 223,634 characters, 60,968 Ollama tokens (E7: 117,945 and 32,525); `reference` 152,931 characters, 41,990 tokens (E7: 77,663 and 21,527). The `reference` prompt no longer fits 32,768, so Qwen ran at 65,536 (deviation, `RUN.md`).

**Binary.** Clean `git archive` export of `8c0526f`, sha256 `4c583e2c…f504a`. Prompts and run script: `87c82d5`. No compiler, book, harness or material change during the run.

## 2. H1: what the hidden tests found

**The gap between "own tests pass" and "hidden tests pass" is 5 cells out of 51** that built, all on the same test. Every failure is listed in `hidden-failures.md`. By class *(hand-scored)*: `other` 5; `authorization`, `rendering`, `redirect`, `session`, `schema` and `naming` 0.

The test (`hidden/t6-orders/Hidden.alder`, "a line posted from a stale page of an order paid meanwhile is refused") works in four steps:
1. It holds an Open order's page.
2. It marks the order Paid with `Db.update`.
3. It submits the held `NewLine` form.
4. It accepts `PageMissing` or `RequestFailed`, with no line stored.

The five FAIL blocks are identical:

```text
left:  { refused: False, lines: 0 }
right: { refused: True, lines: 0 }
```

`lines: 0` means **no program stored the line.** Each program re-reads the order in `update` and refuses. But each refuses with `Reject`, a successful answer that re-renders the page with a message, instead of `Task.fail` or `Task.notFound`:

```alder
-- without/runs/claude-opus/t6-orders-s1/round0/app/Orders/Show.alder
  AddLine p -> {
    let order <- current model session
    match order.status {
      Open -> addLine order p.product p.form.quantity,
      Paid -> Task.succeed (Reject "This order is no longer open."),
      Cancelled -> Task.succeed (Reject "This order is no longer open."),
    }
```

```alder
-- without/runs/claude-haiku/t6-orders-s2/round0/app/Orders/Show.alder
  if not isOpen then Task.succeed (Reject "This order is no longer open.") else if not sellable then …
```

A probe run after the matrix (`logs/probe-t6-stale.alder`: the same steps, ending in the answer itself) gives `left: Rerendered` in all five cells. Chapter 10's table promises `FormRejected` for "`update` answered `Reject`". The reason for the difference is in `rt/testing/browser.go`: the answer is `FormRejected` only when the re-rendered page shows errors. Here the re-rendered page is a Paid order's, and (as the Names block requires) it has no add-line form, so the `Reject` text has nowhere to appear. A user would see the order, now Paid, with no form and no message.

**Reading** *(hand-scored)*. The task text, in both conditions, says only "Adding a line to an order that is not Open is refused by the server, even when the form comes from a page loaded while the order was still Open". It does not say how to refuse.
- A `Reject` that writes nothing is a refusal by the server.
- Chapter 6 recommends `Reject` "when a well-formed submission is refused for a reason only `update` can know".

So these are not faults against what the task fixed: **the hidden test is stricter than the task text.** The two-reference gate could not catch this, because both references used `Task.fail`/`Task.notFound`. If the test accepted `Rerendered` or `FormRejected` with no line stored, every Claude cell would pass every hidden test. The failures are classed `other`, not `authorization`: the order is the user's own, and nothing was written.

**What passed, and means something.** All 51 programs that built passed every hidden test that probes a hole a model could leave:
- another user's note or order is `PageMissing` (T4, T5, T6 for Staff), and a Manager sees it (T6);
- `/products` is Manager-only (T6);
- a stranger's Delete or Publish, from a page the owner held, is `PageMissing` and changes nothing (T5, T7);
- a Delete of a note deleted meanwhile is `PageMissing` (T5);
- a draft is invisible to visitors, readers, other authors and searches (T7);
- each stored comment sends exactly one mail, with the exact subject, to the post's author, and a rejected comment sends none (T8);
- the theme lives in the session across pages and on `/login` (T4).

No program renamed a fixed name, added a field to a fixed table, or put a fixed id or class elsewhere.

**What the hidden tests could not see** *(hand-scored)*.
- **Ordering.** The test clock stands still, so no test can check order. A `grep` over the 21 final T4/T5 rounds shows every one lists notes with `Db.orderBy Note.created.desc`, as asked.
- **The dropped `Reject` text** (above). Only a test that inspects the answer can see it.

**H1 verdict.** On these five tasks, with fixed names, Claude's programs that pass their own tests do what the task asked, as far as 37 browser-level tests per run can tell. The one systematic difference was a choice the task left open. H1's premise ("some programs that pass their own tests still fail hidden tests") held only through a test that over-specified.

- **The paragraph changes the tests a lot.**
  - With it, every cell wrote tests: 6.5 per cell for Haiku, 4.2 for Sonnet, 9.7 for Opus.
  - Without it, Sonnet wrote 1 test across six cells, Opus 9 across three, and Haiku 22 across six. Haiku, and Opus on T5, still write tests unasked, presumably copying the example app, which has them.
  - No `without` T6 program has a test.
- **The paragraph changed the program on T6, and only there.**
  - All five `with` T6 programs refuse a line on a non-Open order with `Task.fail`, and use `Task.notFound` for a missing or foreign order.
  - All five `without` programs use `Reject`, and none uses `Task.fail` (`grep` over the final `Orders/Show.alder`s *(hand-scored)*).
  - The cause is plain in the paragraph: "adding a line to a Paid order is refused (say in a comment whether you chose `Task.fail` or `Task.notFound`, and why)". This does not ask for a test; it names the mechanism, and the models followed it. Sonnet's `with` s1 comment: "Refusal is `Task.fail`, not `Task.notFound`: the order exists and the user may see it; the request conflicts with its state. A 404 would claim the order is missing. Failing rolls back everything, so nothing is written."
  - So the measured H2 effect on T4–T6 (hidden 100% vs 96%) is the paragraph's hint meeting the hidden test's strictness (§2), not a better program. On T4 and T5 the hidden results are identical in both conditions: all pass.
- **Rounds.** Retries are rare in both conditions. On T4–T6, `with` had 1 retry (Haiku T4 s1: an own test failed in r0). `without` had 3, all for check errors: Haiku T4 s1 (E0201), T5 s2 (E0002 + E0201) and T6 s1 (E0001). Writing tests did not cost Claude retries here.

## 8. What changes because of this

For the controller; nothing here was changed during the experiment.

1. **Fix T6's stale-page hidden test before any rerun** (evidence: §2, the five cells in `hidden-failures.md`). There are two ways:
   - accept `Rerendered`/`FormRejected` when no line was stored; or
   - fix the refusal in the Names block ("refused with `Task.fail`", or "a 404").

   Prefer the first: the task asks for a behaviour (nothing stored), not a mechanism. Also add a third reference, or a mutant, that refuses with `Reject`, so the gate exercises the choice the text leaves open.
2. **Book: chapter 10's answer table and chapter 6's `Reject`** (evidence: the probe, `rt/testing/browser.go`). Either:
   - say that a `Reject` from a form the re-rendered page no longer has is answered `Rerendered`, and its text is not shown; or
   - change the runtime so the text is not lost (show it in `<Errors form />` of the page, or answer it like a refused request).

   Today a user who posts from a stale page sees the page change under them, with no message. Decide which, then add the case to chapter 6's "refuse without changing anything" paragraph: a stale-page refusal (the state changed after the page was loaded) is where `Reject` silently drops its text.
3. **Agent reference: when to refuse with what.** With no hint, Haiku, Sonnet and Opus all chose `Reject` for "an order that is not Open". With the hint, all chose `Task.fail`. Models follow whichever the text names (§3), so the reference should give one rule for a well-formed request that the current state forbids: for example, "`Reject` if the page still shows the form; otherwise `Task.fail`", or the reverse.
4. **Task texts: keep implementation hints out of the tests paragraph** (evidence: §3, T6). "Say whether you chose `Task.fail` or `Task.notFound`" changed every program. It belongs in the body of both conditions or in neither. For H2, a tests paragraph that only names behaviours to test changed nothing measurable in the hidden results (T4, T5, T7, T8).
5. **Harness: flag "tests asked, none written"** (evidence: Qwen T5 `with`, `r0 ✓ 0`). Record `own_tests: 0` in the summary and show it in the report, without failing the round: `r0 ✓ 0` already appears, but a `with` cell with 0 tests should read as a miss.
6. **The next experiment should be harder, not larger** (evidence: §1 and §5: 365 / 370, and the three models are indistinguishable). Options, in order:
   1. tasks with less fixed (only the pages and the session), so the hidden tests must work through the browser alone, which the stale-page technique already supports;
   2. larger changes to an existing app (several pages, a role, a migration that must keep data, e.g. splitting a field, where `DROPS DATA` is the easy wrong answer);
   3. a language change that lets a test build another page's message (Task 1's report), so forged requests can be tested directly.

   Keep `--hidden` and the two-reference gate, and add a solution that refuses by `Reject` to the gate (item 1).
7. **Migrations are not a problem at this size** (evidence: §4: 0 / 11 rounds with `DROPS DATA`, and no migration at all in T8). The `column order changed` note is informational; nothing needs to change. H3 needs a task where the obvious schema is lossy (item 6).
8. **Prompt size.** The book roughly doubled since E7 (`sizes.md`): 61k tokens for `full`, 42k for `reference`. Claude was unaffected, but any small local model now needs a 64k window even for `reference`. If Qwen stays (T5 is its first pass), either cut `--reference` further (the growth is chapters 7, 8 and 10; chapters 11–14 are not in the prompt) or add a smaller agent prompt as a condition.
