# E9 survivors and fed-back tests

Sections 1, 3 and 4 are generated by `logs/survivors.py` from the summaries; section 2's rows are generated
from `logs/attribution.jsonl` (`logs/attribute.py`: each fed-back test run alone under mutation on its round),
and its labels are *hand-scored* (the reading rules and the hand labels of the tests that kill no mutant are in
`logs/survivors.py`, `HAND`). Section 5 (equivalence claims) is hand-written from `logs/extract.py claims` (`logs/survivors-claims.md`).
Per-operator kill rates over the final rounds: `logs/operators.md` (`logs/operators.py`).

**Labels.** *real*: the test checks a behaviour of the app (it fails on some mutant, or, read by hand, asserts
something the app does that no operator changes). *wrong-module*: it kills the survivor it answers, but sits in
another module than the one the prompt named (the survivor's). *tautology*: it fails on nothing because it
asserts nothing about the app (`test "x" = True`, or an assertion that holds whatever the code does).
*equivalent-claimed*: a comment instead of a test, saying no input tells the survivor apart (section 5).
Mutants are matched across rounds by module, declaration, operator and rank in source order (`logs/attribute.py`).
Only tests of **accepted** feedback rounds are scored here (355); the tests of the one rejected round and the five
failed rounds never counted (section 3).
