> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second example app, `examples/blog` — posts with slugs, comments with a cascading foreign key, an author role, pagination, search, a Markdown Query capability — with tests in every module, verified by the book's new tour chapter; plus the two language additions it needs: `startsWith` on text columns and the delete rules `@cascade` / `@restrict` / `@setNull` on references.

(2) The app: eleven modules per the spec, a Go adapter for Markdown that builds `rt/html` nodes, tests per module; it checks, builds, serves and passes `alder test`. (3) The book: chapter 8 (search, delete rules), chapter 7 (a Query capability), a new chapter 14 "A second app" whose `part=` blocks are verified against `examples/blog` (the verifier learns `part=blog/<Module>`), chapters 11/12/README.

**Tech Stack:** Go; the existing verifier; SQLite via `rt/db`.

**Spec:** `docs/superpowers/specs/2026-10-10-m5-blog-migrations-fakes-design.md` — "The blog", "Search", "References", "Tests", "Book", and "Decisions recorded". Read it first.

## Review Focus

1. **`Db.delete Post id` with comments under `@cascade`**: expected — the comments are gone (asserted by `Db.count` in a blog test), the trace shows one `Db.delete Post` step, and under `@restrict` (the default) the same delete fails with the existing "a Comment refers to this Post" message. Test in Task 1 (`rt/db` cascade test) and Task 2 (the blog's `Admin.Edit` test).
2. **`@setNull` on a non-`Maybe` column**: expected — E0003 "`@setNull` needs a `Maybe` reference" at the attribute; on a `Maybe` reference a parent delete leaves `Nothing`. Test in Task 1 (corpus + `rt/db`).
3. **Search with `%` or `_` in the query**: expected — matched literally, never as wildcards (`escapeLike` exists for `contains`; `startsWith` must use it too). Test in Task 1 (`rt/db` `StartsWith`), Task 2 (a `Posts.Index` test searching for `100%`).
4. **A page of results past the end** (`?page=99`): expected — an empty list and no error; `page=0` or negative → treated as 1 (a `where` on the parameter in `load`, documented in the tour). Test in Task 2 (`Posts.Index` tests).
5. **The Markdown adapter given hostile input** (`<script>`, `[x](javascript:…)`, unclosed `*`): expected — text is escaped by construction, a `javascript:` link becomes plain text, unclosed emphasis renders as the literal `*`. Test in Task 2 (Go unit tests of the adapter).
