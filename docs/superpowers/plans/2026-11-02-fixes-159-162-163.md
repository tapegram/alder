# Fixes #159, #162, #163 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three independent fixes from roadmap #52: generators accept a non-multi-line `update`
(#159), `Notice` gets success/warning/error variants (#162), and the alder-tui Logs rid filter
says how many newer lines it hides (#163).

**Architecture:** #159 adds one shared rewrite helper in `internal/generate/srcedit.go` that
turns `update`'s body into a multi-line `match msg { … }` before `updateArmSpot` runs; form, msg
and auth call it. #162 threads a variant from `stdlib/Notice.alder` through `rt.Nav`, the signed
`alder_notice` cookie, the toast/alert HTML and the test browser. #163 adds a hidden-line count
to the tui log store and shows it in the Logs strip.

**Tech Stack:** Go, Alder stdlib (`.alder`), alder-tui (Bubble Tea, module `alder/tui`).

**Spec:** GitHub issues tapegram/alder#159, #162, #163 (read them with `gh issue view N`).

  Task 3, run it inside `tui/` (separate module).
- Error and refusal text: plain sentences, matching the house style of the existing refusals in

## Review Focus

- #159: `update` whose match is multi-line but closes as `  B -> y }` (closing brace not alone).
  The user expects a reflow, not a refusal. Pinned in Task 1.
- #159: a catch-all that would be unreachable, because Msg has only the constructors the
  generator adds. Alder's checker rejects unreachable arms (`internal/check/pattern.go:146`), so
  the generated app must still pass `alder check`. Pinned in Task 1.
- #162: notice text that contains `:` (for example "Error: try again") must round-trip through
  the cookie unchanged. Pinned in Task 2.
- #162: an old-format cookie (`notice:<text>`, signed before this change) is still in a browser
  after upgrade. It must show as an info toast, not vanish or garble. Pinned in Task 2.
- #163: the rid filter is set, but every newer line is also hidden by the level filter. The
  count must only include lines the rid filter alone hides; otherwise "x to clear" leads to an
  empty screen. Pinned in Task 3.

### Task 1: #159 — rewrite a non-multi-line `update` into a match

**Files:**
- Modify: `internal/generate/srcedit.go` (near `updateArmSpot`, :445)
- Modify: `internal/generate/form.go:394-397`, `internal/generate/appmsg.go:43-46`,
  `internal/generate/auth.go:302-305` (replace the refusals with a call to the helper)
- Test: `internal/generate/update_rewrite_test.go` (new), `cmd/alder/generate_test.go`
  (refusal row + one golden case)

**Interfaces:**
- Produces: `func matchifyUpdate(src string, m *syntax.Module, added []string) (string, error)`
  in `srcedit.go`. It returns `src` with `update`'s body as a multi-line `match <param> { … }`
  whose closing `}` is alone on its line. If it already is one, or there is no `update`, it
  returns `src` unchanged. `added` holds the Msg constructor names this generator run adds.
  Callers re-parse the result, then call `updateArmSpot` as now.

Rules, where `<p>` is the name of `update`'s first parameter (`msg` in generated code) and `B`
is the old body's source text:
1. The body is a `*syntax.Match` on one line, or its `}` shares a line with an arm: reflow it.
   Write `match <scrutinee> {` on the decl's line, one arm per line from each `Arm`'s span
   (indent: decl indent + 2, trailing comma), and `}` at the decl's indent. Arm text is copied
   verbatim. If the match has a comment inside it (any `--` in its span), refuse instead.
2. Any other body, with a hole (`*syntax.HoleExpr`) among them. If the module's `Msg` type has a
   constructor not in `added`, the body becomes `match <p> {\n  _ -> B,\n}`, and the
   generator's arm is then inserted before `_` by the caller. Note: `updateArmSpot` currently
   inserts before `}`. Adjust it to insert before a trailing `_ ->` arm when there is one, or
   the new arm is unreachable.
3. No other constructor, and the body is a hole: the body becomes `match <p> {\n}` (empty match).
   The caller adds the arm, so the hole is dropped, as the issue specifies.
4. No other constructor, and the body is not a hole: refuse with
   ``"`update` handles no message yet, and its body is not a hole: write it as `match msg { … }` yourself"``.

  `TestMatchifyUpdate_OneLineMatch`, `TestMatchifyUpdate_BraceSharesLine`,
  `TestMatchifyUpdate_CatchAll`, `TestMatchifyUpdate_HoleNoOtherCtor`,
  `TestMatchifyUpdate_RefuseBodyNoOtherCtor`, `TestMatchifyUpdate_RefuseCommentInMatch`,

  `Text -> Nav -> Nav`. `Notice.with` is unchanged (info).
- Produces, in Go: a variant type in `rt` with values `info | success | warning | error`, in the
  repo's style (a string type like `type NoticeKind string` is fine).
  - `std.NavNoticed` takes a kind.
  - `Unnotice()` returns `(text string, kind NoticeKind)`.
- Produces, in test results: `r.notices : List Text` is unchanged (book and examples compare it to
  `["Saved"]`). Add `r.toasts : List { kind : Text, text : Text }`, in the same order, with
  `kind` one of `"info" | "success" | "warning" | "error"`.

Rendering (exact values):

| kind    | al-toast `variant` | toast `timeout` | al-alert `variant` | al-alert `role` |
|---------|--------------------|-----------------|--------------------|-----------------|
| info    | `info`             | `5000`          | `info`             | `status`        |
| success | `success`          | `5000`          | `success`          | `status`        |
| warning | `warning`          | `5000`          | `warning`          | `alert`         |
| error   | `destructive`      | `0`             | `destructive`      | `alert`         |

(`timeout="0"` keeps the toast until it is closed; see book appendix C, :1134.)

Cookie: the signed payload becomes `notice:<kind>:<text>`. When decoding, if the segment after
`notice:` up to the first `:` is a known kind, use it and take the rest as text. Otherwise the
whole remainder is text and the kind is info. This is how an old cookie is read.

- Modify: `tui/internal/ui/logs.go:280-296` (`strip()`)

**Interfaces:**
- Produces: `func (l *Logs) HiddenNewer(f Filter) int`. It counts lines newer than the newest
  line `f` shows that pass `f`'s level and regexp but have a different rid. If `f` shows no lines,
  it counts all lines the rid alone hides. It returns 0 when `f.Rid == ""`.

Strip text when the count is greater than 0: `rid d7831eb7 · 6 newer lines hidden (x to clear)`.
Use `line` when there is exactly one hidden line. When the count is 0 the strip is unchanged, so
`TestLogs_Follow:29` (`" level info"`) still holds. Do not auto-clear the filter.
