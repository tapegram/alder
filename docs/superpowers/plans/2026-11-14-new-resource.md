# `alder new resource` Implementation Plan (#194)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `alder new resource <Table>` writes user-scoped list/show/new/edit/delete route modules
for a table (with `--read owner|signed-in|all`), `alder regen resource` keeps them in step with the
schema, and the pieces `new form --edit T` and `new route --list T --search` work on their own.

**Architecture:** Admin's generator (`internal/generate/admin.go`) becomes a shared CRUD generator
(`crud.go`) parameterised by an `access` value that says whose rows the pages reach, how routes
are guarded and which region marker the files use. Admin builds `adminAccess`; the resource builds
`resourceAccess` from the table's key and `--read`. Regions, header, regen and tests are admin's
machinery with the `@resource` marker.

**Tech Stack:** Go (generator, CLI), Alder (generated code and its tests), golden files under
`testdata/generate/want/`, the book (`book/*.md`, snippets tested).

**Spec:** `docs/superpowers/specs/2026-11-14-new-resource-design.md` (read it; this plan argues
from it and does not repeat its tables).

## Global Constraints

- Four PRs, each merged to main before the next starts (no long-lived side branches): PR 1 = Tasks 1–3,
  PR 2 = Tasks 4–10, PR 3 = Task 11, PR 4 = Task 12. Task 13 files follow-ups after PR 4.
- PR 1 changes no output: every golden under `testdata/generate/want/` byte-identical
  (`git diff --exit-code testdata/` after `go test ./cmd/alder -run TestGenerate -update`).
- Ownership code is never hand-rolled: on an `@owner`/`@partition` table, writes use
  `insertMine|updateMine|deleteMine` (`…Scoped`); unscoped `Db.*` appears only for blocker counts,
  `@unique` counts and reference selects over unowned tables, each with a one-line `--` comment.
- Paths: collection = `"/" + names.Collection(T)`; members `/{id}`, `/new`, `/{id}/edit`,
  `/{id}/delete`; methods GET/POST/PUT/DELETE as spec §2's table.
- Module default `PluralConcern(T)`; route names `Index`, `Show`, `New`+`Create`, `Edit`+`Save`,
  `Delete`+`Destroy`; form name `<T>Form`; delete form `Confirm` (admin's).
- `perPage` is 20 for a resource, 25 (`bulkMax`) for admin.
- Header exactly: ``-- generated by `alder new resource <T> --module <M> --path <p> --read <r>[ --requires <k>]`; regions between``
  newline ``-- `-- @resource begin <name>` / `-- @resource end` are rewritten by `alder regen resource` ``.
  `--read` is always written; `--requires` only when given explicitly.
- Refusals: one sentence, exit 1, nothing written, via `Refusef`. Warnings through
  `Result.Warnings` (printed `alder new resource: warning: …`).
- Generated tests pass `alder test` and the mutation gate ≥ 0.95, as admin's.
- Usual gate per task: `go test ./internal/generate ./cmd/alder` green. Book snippets are tested
  (`go test ./book/...` or the repo's book test; run what `make test` runs for the book).

## Review Focus

1. **Another user's id under `--read signed-in|all`.** Show displays it, but Edit/Save/Delete/Destroy
   must 404 and leave the row unchanged. Pinned by the generated tests in Task 7 and by
   `TestResource_NoUnscopedWrites` (Task 5), which greps every resource file of an owned table for
   `Db.get `, `Db.update `, `Db.delete `, `Db.insert ` outside a commented line.
2. **A multi-word table** (`BlogPost` → module `BlogPosts`, path `/blog-posts`, noun "blog post").
   Pinned by the `fixture-resource-create` golden (Task 8), which creates `BlogPost`.
3. **Author edits, then regen.** Text outside regions kept byte for byte; a region whose markers were
   deleted is not re-added; a deleted file is not recreated without `--all`. Pinned by
   `TestResource_Regen` (Task 9).
4. **Header round trip with non-default options** (`--module Mine.Posts --path /my/posts --read all
   --requires user`). Pinned by `TestResourceHeader_RoundTrip` (Task 9).
5. **An existing `/posts` route** (from `new route Posts.Index /posts --list Post`) with another
   `--module`: refused by `clashRefusal` before anything is written. Pinned by the refusal case
   `resource-clash` (Task 6).

**Files:**

- Produces (in `crud.go`):

```go
// access says whose rows a set of pages reach and how its routes are guarded.
type access struct {
	marker  string // "@admin" | "@resource": region markers
	header  string // the file's two header lines, without the trailing newline
	gate    string // first statement of every load/update: "let _ <- Admin.Layout.adminOnly session.user" | ""
	layout  string // the view's root component: "Admin.Layout.Page" | "Layout.Page"
	layoutImport string // "Admin.Layout" | "Layout"

	readRequires  string // Index and Show: " requires user, role Admin" | " requires user" | " requires user, org" | ""
	writeRequires string // New/Create, Edit/Save, Delete/Destroy
	sel           string // Index's rows and count: "Db.from" | "Db.mine" | "Db.scoped"
	get           string // Show's load: "Db.get" (Maybe) | "Db.getMine" | "Db.getScoped"
	writeGet      string // the load on Edit and Delete and before Save/Destroy: as get, for writes
	insert, update, remove string // "Db.insert"|"Db.insertMine"|"Db.insertScoped", likewise update/delete
	ownerOnly     string // "" | "session.user == row.<owner>" | "session.user == Just row.<owner>"
	perPage       int    // 25 admin, 20 resource
}

func adminAccess(o AdminOptions) access
func (a access) maybeGet(get string) bool // get == "Db.get"
// found is the statements loading row `row` of t by idExpr with get: for Db.get,
// `let found <- Db.get T id`, then between, then `match found { Just row -> { body }, Nothing -> notFound, }`;
// for getMine/getScoped, `let row <- <get> T id`, then between, then body.
func (a access) found(get string, t *Table, idExpr string, between, body []string, notFound string) []string
```

- `crudGen.load`/`update` emit `a.gate` only when non-empty; `regionAt`, `testsText`, `siloCode`'s
  cut use `regionBegin(g.a.marker)`; `file` writes `g.a.header`; `layoutOpen` uses `a.layout`;
  `index` uses `a.perPage` and `a.sel`; `show`/`edit`/`delete` load through `found`; `newPage`/
  `edit`/`delete` write with `a.insert`/`a.update`/`a.remove`; `crudTable.requires()` returns
  `a.readRequires` (or `a.writeRequires`, by a `write bool` parameter) plus admin's silo suffix.
- Do not route the bulk page, the dashboard, the silo picker or the test-side `Db.get` lines in
  `admin_bulk.go` through `access`: they are admin-only.

type ResourceOptions struct {
	Table    string
	Fields   []FieldSpec // create the table first when given
	Read     string      // "owner" | "signed-in" | "all"; "" = default
	Requires string      // as given; "" = default
	Module   string      // "" = PluralConcern(Table)

}
// resourceCheck fills the defaults and refuses what spec §1 refuses; it returns the table and
// the route keys (routeGuard's).

- Defaults (spec §1): `Read` = `owner` on an `@owner`/`@partition` table, else `signed-in` when the
  session has `user`, else `all`. `Requires` = the table's key through `routeGuard` (`user`;
  `user, org` for `@partition org` with `via`); keyless: `user` with a session user, else "".
- Refusals, exact text from the spec where it gives one:
  - no such table and no fields: "there is no table `Post`: give its fields to create it
    (`alder new resource Post title:Text`) or make it first with `alder new table`"
  - fields on an existing table: "`Post` exists: change it with `alder edit table Post add-field …`, then `alder new resource Post`"
  - silo: "`Activity` lives in the `org` silo: `alder new resource` writes pages over the shared store only (the admin shows siloed tables)"
  - `app/<Module>/` exists: "`app/Posts/` exists: `alder regen resource Post` updates it; to generate another, choose another `--module`"
  - `--read owner` keyless, `--read` on a partitioned table, explicit `--requires` without the key,
    `--read all` on `@owner` with no session user: spec §1's sentences verbatim.
  - bad `--module`/`--path`: admin's sentences (`adminCheck`), with `/posts` as the example.
  - a required secret with no default (admin's sentence); a required non-owner `@ref User`:
    "`author` is required and refers to users: give it a default or make it `Maybe`".
  - `--requires user` with no session `user`: `routeGuard`'s text.
