# M14: Deploy — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A checked `deploy` declaration in `App`, `alder deploy <env>` running the fixed gate and shipping a build to an `Ssh`, `Fly` or `Script` target with backup, migration, health check, switch and rollback, state at the target keyed by build id, a streaming backup, `alder ci init`, and chapter 16.

**Architecture:** (1) Language: the `deploy` declaration, E0030, the IR record, `requires` derivation. (2) The deploy engine (`internal/deploy`): gate → artifact → target interface → ship/switch/rollback/status/logs; the `Script` and `Ssh` targets; the backup shipper in `rt`. (3) The `Fly` target, `ci init`, chapter 16 and the rest of the book, the reference.

**Tech Stack:** Go (`golang.org/x/crypto/ssh` is NOT allowed by the import rule — use the system `ssh`/`scp` binaries via `os/exec`, which also honours the user's agent and config; the Fly machines API over `net/http`; S3 via the REST API with SigV4 in stdlib `crypto/hmac`), Caddy at the target (installed by the Ssh target if absent, admin API on localhost), systemd units.

**Spec:** `docs/superpowers/specs/2026-10-16-m14-deploy-design.md` (binding: the declaration's shape and E0030 texts, the command's steps and refusals, state at the target, the gate, the data-loss rule, the targets' behaviours).

## Global Constraints

- Imports stay stdlib + `alder/*` + modernc; SSH through the system binaries; no new Go dependencies.
- No secret ever in `App.alder` (E0030), in the artifact, in `deployed.json`, or in logs; `requires` names only.
- The gate cannot be weakened from the file: `--unsafe-skip-tests` and `--allow-data-loss` are command-line only and recorded in `deployed.json`.
- Nothing is switched before the health check passes by build id; a failed deploy leaves the previous build serving and the new build's directory for inspection.
- Both examples gain a `deploy` declaration with a `Script` environment used by the tests, and keep their scores; migrations untouched.
- Gate: `gofmt -l $(git ls-files '*.go')` empty; `go vet ./...` (all tags); `go test ./... -count=1 -timeout 30m`; `-tags deploy` in CI (Docker sshd); both examples check/test/`--mutate`; `alder new` out of tree + `alder deploy` to a `Script` target; experiments unittest (reference ≤ 47k); `go test ./book`.
- Commit messages end with the session trailers; stage by explicit path.

## Review Focus

1. **A deploy whose migration drops data**: refused without `--allow-data-loss` with the DROPS DATA lines; with the flag, the backup is taken BEFORE the migration and `deployed.json` records the flag. Task 2.
2. **A health check that never passes** (the new build crashes at start, or a wrong `ALDER_SECRET` length): nothing switched, the old build still serving, the new build's log in the refusal, `builds/<id>/` kept. Task 2.
3. **Rollback to a build whose schema snapshot is older than the live schema**: refused by default with the table names; `--allow-schema-mismatch` proceeds; the data is untouched either way. Task 2.
4. **A `requires` name missing at the target** or set to empty: refused before any upload, naming it; a secret-looking literal in `App.alder` is E0030. Task 1 (checker) + Task 2 (target).
5. **The preview environment on a pull request**: `ci init`'s workflow deploys `preview` with the PR number in the host and comments the URL; a second push updates it; closing the PR leaves it (documented; cleanup is a follow-up). Task 3 (workflow golden + a `Script` dry run).
