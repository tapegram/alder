**Design (binding), message by message (exact texts; the corpus pins them):**
1. In module `M`, a qualified reference `M.x` → `E0201`? No: a new wording under E0002: "inside `M`, its own names are written unqualified: `x`" with a fix replacing `M.x` by `x`; never "module `M` is not imported".
2. `X.y` in module `M` where `X` is not imported AND `X` (transitively) imports `M` → E0201 "module `X` is not imported, and it imports `M`, so `M` cannot import it; a test of `X` belongs in `app/X.alder`" with NO fix. (Use the dependency graph `graph.go` already builds; the message is emitted during resolution of `M`, which runs after the graph exists — confirm the order; if resolution runs before the graph, compute reachability from the import lists alone, which are parsed already.)
3. `import X` where no module `X` exists → E0002 at the import: "there is no `app/X.alder` (or `app/X/…`): write the module or remove the import"; every later `X.name`, and every unqualified constructor/type that is unresolved and would have been found in `X` had it existed, is NOT reported (the import's error stands for them). Implementation: the resolver records `missingImports`; `X.y` with `X` missing → silent; an unresolved unqualified constructor → silent only when some missing import exists AND the name is not declared anywhere in the app (keep E0002 when it is declared somewhere: that is message 4).
4. Unqualified constructor `C` unresolved, declared by exactly one app module `X` not imported → E0002 "`C` is a constructor of `X.U`; import `X`" with the import fix (E6's proposal); declared by two or more → "`C` is a constructor of `X.U` and of `Y.V`; import one of them" with no fix. Types likewise ("`T` is a type of `X`; write `X.T`" already exists as E0202 — leave).
5. A test (or any code) in module `M ≠ App` calling `App.update` → E0002 "`App.update` is called by the runtime, not by code; a test of it belongs in `app/App.alder`" (today: "`App` has no `update`", false).
6. `if` in markup without `else` → E0001 "`if` always has an `else`; in markup write `else Html.none`" at the point the parser expected `else`; in expression position the existing message gains "; `if` always has an `else`".
7. Trailing comma after a block's last expression → the existing E0001 gains "; the last expression of a block is its result and takes no `,`" (E6's proposal).
8. E5 problem 2: `Post.Comment` where `Comment` is a table declared in module `Post`… read E5's description in `experiments/e5-loop/findings.md` (problem 2) and chapter 12; the fix offered (`import Post.Comment`) names a module that does not exist; message: "`Comment` is a table of module `Post`; write `Post.Comment` after `import Post`" with that fix when `Post` exists — or whatever the real shape is; pin it.
9. `arith`: when `Unify` fails and both sides are numeric brands of the same base, return the base type (chapter 4 rule 3; the same-brand case already returns the brand because Unify succeeds). `Cents + Cents : Cents` unchanged; `Int.NonNegative * Int.Positive : Int`; `Cents + Int.Positive : Int`.
