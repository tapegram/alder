# M3d Dev Loop and E6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `alder run examples/todos` serves the app, rebuilds on every save, shows compiler errors in the browser, and reloads the page after a successful rebuild; the experiment harness gains a `--build` round and its deferred fixes; experiment E6 measures, for the first time, whether agents' programs *compile and build*, and its findings land in the book.

**Architecture:** `alder run` is a dev server in front of the app's own binary: it builds the app with the same pipeline as `alder build`, starts the binary as a child on a free port (`ALDER_ADDR=127.0.0.1:0`, `ALDER_DEV=1`, `ALDER_RELOAD=1`, `ALDER_STATIC=<app>/static`), reverse-proxies to it, polls `app/**/*.alder` and `adapters/*.go` every 300 ms, and on change re-runs check → build; a failed check is pushed to the browser as an SSE patch into an overlay; a successful build starts the new child, swaps the proxy target, stops the old child, and pushes a reload. The app's router, when `ALDER_RELOAD=1`, injects the reload subscriber and the overlay container into every page — no HTML rewriting in the proxy. The harness runs `alder build --emit` after a passing check so a round counts as "compiles" only if the generated Go vets.

**Tech Stack:** Go 1.27 stdlib (`net/http/httputil`, `os/exec`, `os/signal`); Python 3 stdlib for the harness; Ollama (`qwen3-coder:30b`) and the `claude` CLI for E6.

**Spec:** `docs/superpowers/specs/2026-10-09-m3-codegen-runtime-design.md` ("Dev loop", "Harness", Milestone M3d). Harness: `experiments/README.md`, `experiments/run_loop.py`, `experiments/e5-loop/findings.md` (the deferred items). Book: `book/11-tooling.md`, `book/12-rationale.md`, `book/13-compiler.md`.

## Global Constraints

- Go `1.27`, module `alder`; `cmd/` and `internal/` import stdlib only; `rt/web` stdlib only.
- `gofmt -l $(git ls-files '*.go')` empty; `go vet ./... && go test ./...` green before every commit; `python3 -m unittest` in `experiments/` green; `alder check examples/todos` clean; `alder build examples/todos` exits 0.
- The dev server listens on `ALDER_ADDR` (default `:8080`); children always get `127.0.0.1:0` and print `listening on <addr>`; the dev database is `build/<app>/dev.db` and persists across restarts (schema recreate on change is the runtime's job); the poll interval is 300 ms; a restart is graceful (new child up and answering before the old one gets SIGTERM; the old one has 5 s).
- Browser messages: a failed check pushes `datastar-patch-elements` `selector #_alder_errors` `mode inner` with the rendered diagnostics (escaped, in a `<pre>`); a successful rebuild pushes `datastar-patch-elements` `selector body` `mode append` `<script data-effect="el.remove()">location.reload()</script>`; a crashed child is reported in the terminal and in the overlay, and the dev server keeps serving the last good binary.
- Harness: a round passes only if `alder check --json` has no errors **and** (with `--build`) `alder build --emit` exits 0; the build result is recorded per round as `build: {ok, exit, stderr}`; a build failure after a clean check is a compiler bug and is filed in the experiment's findings with a repro under `repros/`.
- E6 is recorded like E5: `experiments/e6-build/{prompt.md,tasks/,runs/,repros/,scores.md,findings.md}` and a chapter-12 entry; every number in findings comes from `summary.json` files in `runs/`.

## Review Focus

1. Saving a file with a parse error, then saving a correct file within one poll interval — the overlay must clear and the page reload, never a stale error (Task 1 `TestRun_ErrorThenFixReloads`).
2. The child crashing at startup after a rebuild (e.g. `Serve` refuses because an adapter is missing) — the old server must keep answering and the overlay must show the child's stderr (Task 1 `TestRun_ChildCrashKeepsOld`).
3. Two saves within 300 ms — exactly one rebuild, not two overlapping children (Task 1 `TestRun_CoalescesSaves`).
4. Ctrl-C on `alder run` — the child must be terminated, no orphan on the port (Task 1 `TestRun_StopKillsChild`).
5. A model answer whose generated Go fails to vet after a clean check — the harness must record it as a build failure and still write the round (Task 2 `test_build_failure_recorded`).

- Test fixtures: a temp copy of `examples/todos`

**Interfaces:**
- `build.go`: `func buildApp(dir string, stderr io.Writer) (binary string, code int)` — the body of `runBuildTo` after flag parsing: check (diagnostics to `stderr`, code 1), emit, adapters, static, `cmd/main.go`, vet, `go build`; returns the binary path on success. `runBuildTo` calls it.
- `run.go`:
  ```go
  func runRunTo(args []string, stdout, stderr io.Writer, stop <-chan struct{}) int
  // args: [dir]; env ALDER_ADDR (dev server, default ":8080"); stop closes on Ctrl-C (main wires os/signal).
  type devServer struct {
      dir, app  string
      proxy     *httputil.ReverseProxy   // target swapped under a mutex
      child     *child                   // current
      clients   map[chan []byte]struct{} // /_dev/reload subscribers (SSE)
      lastErr   string                   // last check/build/crash text for the overlay
  }
  type child struct{ cmd *exec.Cmd; addr string; stderr bytes.Buffer }
  func startChild(binary, dbPath, staticDir string) (*child, error)   // waits for "listening on" (10 s) else returns stderr
  func (c *child) stop()                                             // SIGTERM, wait 5 s, SIGKILL
  func (d *devServer) rebuild()                                      // check→build→start→swap→stop old→push reload; on check error push overlay; on crash push overlay + keep old
  func watch(dir string, interval time.Duration, stop <-chan struct{}, changed chan<- struct{})  // polls mtimes of app/**/*.alder and adapters/*.go; coalesces: one event per quiet interval
  ```
  Routes on the dev server: `/_dev/reload` (SSE: `text/event-stream`, sends `: ready\n\n` then holds; on rebuild success `datastar-patch-elements` reload event; on failure the overlay event; heartbeat `: ping` every 15 s), everything else proxied to the child (502 with the overlay text when no child is up).
- `rt/web`: `Options.Reload bool`; when set, `withScript` also inserts, right after `<body…>`, `<div id="_alder_errors"></div><div data-on-load="@get('/_dev/reload')"></div>` (the app's `Serve` sets it from `ALDER_RELOAD`).

### Task 2: Harness — `--build` round and the deferred fixes

**Files:**
- Modify: `experiments/run_loop.py`, `experiments/report_loop.py`, `experiments/test_run_loop.py`, `experiments/README.md`

**Interfaces:**
- `run_loop.py`:
  - `--build`: after a round's check passes (exit 0, no errors), run `alder build --emit <round_dir>` (cwd = round dir's parent? — `alder build --emit` writes `build/<app>/` under the CURRENT working directory: run it with `cwd=round_dir` so output lands in `round_dir/build/`); record `round["build"] = {"ok": exit == 0, "exit": exit, "stderr": stderr[-4000:]}`; `final_pass` requires `build.ok` when `--build` is set; a build failure feeds the retry prompt as "the program type-checks but the generated Go does not compile — this is a compiler bug; do not change your program" and STOPS retrying for that task (record `summary["compiler_bug"] = True`).
  - `ClaudeModel.generate`: runs with `cwd=tempfile.mkdtemp()` (no CLAUDE.md, no project settings), passes `--system-prompt <system text>` instead of concatenating it into the prompt (the TASK goes on stdin), records `{"seconds", "claude_version": output of claude --version (cached), "model": self.name}`.
  - `OllamaModel.generate`: records `prompt_eval_count` and `eval_count`; if `prompt_eval_count` is absent or `< 0.9 * estimated_prompt_tokens` (estimate = `len(prompt) / 4`), adds `"warning": "prompt may have been truncated (prompt_eval_count=N, estimated=M)"`.
  - `summary.json` gains `"harness": {"build": bool, "retries": n}`.
- `report_loop.py`: one column per round (`r0 … rN`), each `errors (build ✓/✗)` when build ran; a final column `result` ∈ pass / fail / compiler-bug.
