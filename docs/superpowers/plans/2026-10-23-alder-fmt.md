# alder fmt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A canonical, option-free formatter for Alder: `alder fmt`, LSP format-on-save, and fmt-clean output from every generator.

**Architecture:** The lexer keeps `--` comments in a side list on `Module`; a new package `internal/format` attaches them to AST nodes by position, walks the AST into a Wadler-style document IR, renders it at width 100, and refuses to return output unless a re-parse yields the same `syntax.Dump` and the same comment sequence. The CLI, the LSP and `internal/generate` all call one entry point, `format.Source`.

**Tech Stack:** Go (module `alder`), no new dependencies; tree-sitter grammar in `tree-sitter-alder/`.

**Spec:** `docs/superpowers/specs/2026-10-23-alder-fmt-design.md` — read it first; style rules live in its §4 and are not repeated here.

## Global Constraints

- No configuration: no flags or files that change style. Width `100` (runes), indent `2` spaces, LF, one trailing newline.
- Never write output that fails the safety check (Dump equality + comment-sequence equality). There is no `--fast`.
- Parse error → no output (CLI skips the file with diagnostics; LSP returns `null`).
- Messages are prefixed `alder fmt: `; exit codes 0 clean, 1 would-reformat/parse error, 2 usage/IO/internal.
- Literals, strings (including interpolations), holes, `<script>`/`<style>` bodies and comment text are printed verbatim from source.
- Never insert parentheses to create a line break; emit the minimal parens precedence requires.
- Performance: 1000-line file < 5 ms after parse; all of `examples/` < 200 ms.
- Package name `format` (not `fmt`). Go test files follow the repo's `-update` golden convention.
- Working hours: no agent work 9am–5pm America/New_York, Mon–Fri.

## Review Focus

1. **Comments in awkward places** — between a signature and its value, after `=` before the body, inside an empty record/list, between a match arm's `->` and its body, after the last import. Expect: kept, on their own line, near where they were; never dropped. (Test: Task 7 `fmt_comments` golden cases.)
2. **Markup with significant spaces** — `<p>Hello <b>{name}</b>, welcome back to the dashboard of things that are long</p>` past 100 columns. Expect: the rendered HTML is identical (whitespace between text and `<b>` survives); the line may stay long. (Test: Task 6 golden case `inline_run_long`.)
3. **`--` that is not a comment** — inside a string, inside `<script>`/`<style>`, inside markup text (`<p>a -- b</p>`). Expect: untouched and not collected as a comment. (Test: Task 1 lexer test.)
4. **Format-on-save mid-edit** — buffer with an unclosed `{`. Expect: LSP returns `null`, buffer unchanged, no error popup. (Test: Task 9.)
5. **`regen admin` then `fmt`** — region markers stay alone on their lines, `parseRegions` still accepts the file, and `fmt` after `regen` is a no-op. (Test: Task 10.)

### Task 4: `format.Source`, safety check, declarations and types

**Files:** Create `internal/format/format.go`, `print_decl.go`, `format_test.go`; goldens `testdata/golden/fmt_decls.alder`/`.golden`, `fmt_types.alder`/`.golden`, `fmt_domain.alder`/`.golden`

- Produces: `func Source(file string, src []byte) ([]byte, []diag.Diagnostic, error)` — returns `(nil, diags, nil)` on parse error; `(nil, nil, ErrUnsafe)` (wrapped with the file name) when the check fails; `var ErrUnsafe = errors.New("formatting changed the program")`. `type printer struct` holds `src []byte`, `lines []string` and comment attachments; `func (p *printer) spanText(s diag.Span) string` returns the verbatim source of a span. `func (p *printer) expr(e syntax.Expr) Doc` is a stub here (Task 5 fills it).
