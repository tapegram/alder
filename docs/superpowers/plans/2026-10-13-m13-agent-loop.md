# M13: The agent's loop — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The commands E11 lacks (`new auth/type/decl/test`, `new page --blank`, `fill --decl`, `new msg --in-for`, `edit page add-param`) proven by a recorded drill that builds the E9 teams app with no file edit; boosted navigation on by default with the flash fixed; admin filters, a self-guard and an option-load limit.

**Architecture:** (1) `internal/generate` grows the generators and `fill --decl`; the drill test replays a command script. (2) `rt/web` + `rt/datastar` answer Datastar GETs with body/title/history patches and turn redirects into morphs; the meta tag, the cache header, alder-ui v0.1.3. (3) The admin generator gains filters, the guard and the limit; examples regenerated.

**Tech Stack:** Go (`crypto/pbkdf2`, `crypto/subtle`), Datastar v1.0.0 (vendored), alder-ui.

**Spec:** `docs/superpowers/specs/2026-10-13-m13-agent-loop-design.md` (binding: the command list and their refusals; the real adapter; boost on by default with the opt-out; the admin behaviours).

## Global Constraints

- M12's generator contract holds for every new command (copy → check → write; refuse-not-overwrite; deterministic; `--json`; `--dry-run`); generated tests kill their code's mutants (the gates stay at their scores; the drill app scores ≥ 0.90).
- The password adapter uses only the Go standard library (`crypto/pbkdf2`, `crypto/sha256`, `crypto/rand`, `crypto/subtle`); 600,000 iterations; 16-byte salt; the stored text is `pbkdf2-sha256$<iter>$<salt b64>$<hash b64>`; a constant-time compare; never logs a password.
- Boosted navigation changes no language surface and no test answer: both examples' tests pass unchanged; cross-origin and opted-out links are plain navigations.
- `alder-ui` v0.1.3 adds only `@view-transition` (and nothing else); re-vendored by `scripts/vendor-al.sh`.
- The drill test runs the recorded script end to end and passes the E9 T10 hidden tests; a step needing a command the spec lacks is added to Task 1 and reported.
- Gate: `gofmt -l $(git ls-files '*.go')` empty; `go vet ./...`; `go test ./... -count=1`; both examples check/build/test + `--mutate`; `alder new` out of tree + `alder new auth` there; `(cd experiments && python3 -m unittest)`; `go test ./book -count=1`; reference ≤ 45k.
- Commit messages end with the session trailers; stage by explicit path.

## Review Focus

1. **`alder new auth` on an `App.alder` that already has an `update` with arms, imports, and a session with other fields**: expected — the session gains `user` (and `role`), `login` is inserted, `Logout` added as a new arm, nothing else moves; on an `App` with no `update`, one is created. Test in Task 1 (both shapes, goldens).
2. **A boosted click on a link whose target answers 404, 500, or a Redirect to an external URL; back/forward after two boosted navigations; a link with `target="_blank"`, a modifier-key click, `data-alder-reload`**: expected — 404/500 morph the error body with the status header; the external redirect is a real navigation; popstate refetches and morphs; the four exceptions are plain navigations. Test in Task 2 (router tests with the Datastar header; the exceptions by reading the emitted attribute logic — a unit test on the selector function).
3. **The password adapter against a wrong password, an unknown email, a stored hash with a different iteration count, and a malformed stored text**: expected — `Nothing`, `Nothing`, verifies with the stored count, an error (not a panic). Test in Task 1.
4. **The admin's self-guard with the Admin editing their own row without changing the role, and an Admin demoting ANOTHER admin**: expected — allowed, allowed. Test in Task 3.
5. **`fill --decl` on `update` with a body that drops an arm the view's buttons send**: expected — refused by the checker (exhaustiveness), nothing written. Test in Task 1.
