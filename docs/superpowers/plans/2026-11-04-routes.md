# Routes replace pages, Response replaces Nav — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every URL of an Alder app is a `route NAME = METHOD "path" { params } [form F] [requires …]` with qualified `R.load`/`R.view`/`R.update` declarations; a write route answers an opaque `Response` (`redirect`, `render`, `refresh`, `invalid`, `toast`), and the request decides delivery (document, body morph, element patch by root `id`).

**Architecture:** Ten PRs to `main`, each green and mergeable on its own. The new syntax first lands *beside* `page`/`msg` (PRs 1–5), the generators, the in-repo apps and the book move to it (PRs 6–8), and PR 9 removes the old syntax. PR 10, the `input=`/`load=`/`intersect=`/`every=` attributes, is a later slice that may wait. The runtime (PR 1) is built and tested at the Go level before the compiler emits anything for it.

**Tech Stack:** Go (compiler under `internal/`, runtime under `rt/`), Datastar v1.0.0 (vendored, `rt/datastar`), tree-sitter (`tree-sitter-alder/`), Lua (`~/projects/alder.nvim`), TypeScript (`~/projects/alder-vscode`), Playwright browser tests (`-tags browser`).

**Spec:** `docs/superpowers/specs/2026-11-03-routes-design.md` (approved 2026-11-04, #160). Read it before any task; this plan argues from it and records only the decisions it leaves open.

## Global Constraints

- Route line, verbatim shape: `route NAME = METHOD "path" { params } [form F] [requires …]`. Methods: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`. `form F` on write routes only.
- Member signatures, exactly: GET `R.load : R.Params -> Session -> Query m` and `R.view : m -> Session -> Html` (one `m`); write `R.update : R.Params -> Session -> Task Response`. Signatures stay required.
- Builders shipped: `Response.redirect : Route -> Response` (303), `Response.render : Route -> Response` (200), `Response.refresh : Response` (200), `Response.invalid : Text -> Response` (422), `Response.toast : Text -> Response -> Response`, `Response.success`, `Response.warning`, `Response.error` (same shape as `toast`).
- Not built (no stdlib entry, no runtime code): `Response.status`, `header`, `json`, `file`, `remove`, `patch`, `stream`. The Go `rt.Response` is *shaped* for them (status, headers, events, body).
- `invalid` is a committed success: its Task commits; writes and `Session.put` are kept.
- `redirect` is never diffed, even to the shown route. `render` and `redirect` never render a before-view.
- Request headers: `Alder-Page` (path and query of the page the browser is on) on every write sent from the page; `Alder-Build` on every Datastar request. A build mismatch answers a full reload, never a patch.
- `_method` override is honoured on `POST` only. A request whose method no route declares for a path is `405` with `Allow`.
- No-JS answers: `redirect r` → 303 to r; `refresh` → 303 to the referring page (`Referer`, else `/`); `render r` → 303 to the referring page; `invalid t` → 422 with the referring page rendered, form kept, error shown.
- A view delivered "from an element" has a single root element with an `id`; otherwise: logged, shown in the dev panel, DOM untouched.
- `input=` debounce: 300 ms.
- Book wording for the state rule, verbatim: "If you would want it back after a refresh, it goes in the URL. If it is secret, it goes in the session. Everything else rides in the HTML or is a row."
- `Notice.with`, `Notice.success`, `Notice.warning`, `Notice.error` stay one release as aliases of the `Response` builders, with a deprecation warning naming the replacement.
- Diagnostic codes (this plan's choice; the spec leaves them open): **E0043** route declaration, **E0044** route name, **E0045** route target kind, **E0046** removed syntax (PR 9), **W0012** `Notice.*` deprecated (PR 9). W0005 moves to `Response.invalid`. Each code gets an `internal/diag/explain.go` entry and at least one `testdata/corpus/<case>/` directory.
- Models per task (user's CLAUDE.md): Sonnet for well-specified implementation and write-ups, Opus for runtime- or security-sensitive work and first reviews of risky code, Fable for the final whole-branch review of PR 1 and PR 9. Each task names its model.
- Weekdays 09:00–17:00 America/New_York: no subagents or background runs. A dispatch made under a waiver quotes the user's words and the date at the top of the prompt.
- Quick loop `scripts/test.sh -short`; full `scripts/test.sh` plus `go vet ./...` before each PR. `cd experiments && python3 -m unittest` before PRs 6, 7 and 9.

## Plan calls (decisions the spec leaves to the builder)

1. **Coexistence, then removal.** PRs 2–8 accept `page`/`msg` and `route` side by side; a module holds one or the other (E0043). Old pages link to routes and back. PR 9 removes the old syntax.
2. **`Html` with no argument means `Html Route` until PR 9.** A click names a route, a route constructor has type `Route`, so a route module's markup is the old `Html m` at `m = Route`. Layout components written `Html a` serve both worlds. PR 9 makes `Html` nullary and rejects an argument.
3. **`Page` becomes `Route`.** Prelude declares `type Route` and, until PR 9, `type Page = Route`. In Go, `rt.Route` replaces `rt.Page` with `type Page = Route` kept until PR 9. `Url.external` returns a `Route` with `Method "GET"` and no `Name`.
4. **`Session` in a route member's signature is that route's session**, narrowed by its `requires`, as `Session` in a page module is today. Outside a route member it is App's session. `R.Session` names it explicitly, like `R.Params`.
5. **Route constructors need no import** across modules, as page values today. Route members (`Todos.Row.view`, `Todos.Row.Params`) need `import Todos`, like any value or type.
6. **Go names:** a qualified declaration `Row.view` in module `Todos` is `GoName("Todos.Row", "view")` = `Todos__Row__view`. E0044 forbids a module `Todos.Row` beside a route `Row` in `Todos`, so the scheme is injective.
7. **Element fetches carry `Alder-Fetch: 1`.** A Datastar GET without it is a boosted navigation, as now; a tab from an older build keeps working.
8. **`Alder-Page` is `location.pathname + location.search`**, sent by the page's post helper. Without JavaScript the router uses `Referer`. Both go through `rt.BackURL`, which keeps the path and query, drops scheme and host and refuses `//` paths.
9. **A stale-build write still runs.** Its decoders guard it. The answer is then a reload: `redirect r` navigates to r; anything else reloads `Alder-Page`. A toast is stored in the notice cookie so the reloaded page shows it.
10. **A form that does not decode** on a write route is answered like `invalid` with the field errors: 422, the shown page re-rendered with the form state, `update` not called.
11. **`<Select options={…}>` checks** move to the shown page. A write route with `form F` runs the options check of the GET route the form was posted from (`Alder-Page`, else `Referer`) when that route's view renders a select for F. A post from anywhere else, when F has such selects, is `400 Bad Request`, logged with the reason.
12. **Reachability is conservative.** A write route renders a before-view when its `update` mentions `Response.refresh` or `Response.invalid`, or calls an app function whose result type contains `Response`.
13. **Migration names.** The command is `alder fix --routes [--name N] [file…]`. A message becomes `route M = POST "<page path>/_/<M>" { <page path params>, <payload> } [form F]`; `/` gives `/_/<M>`. The page's *path* parameters join the message route's parameters, so `Show`'s `Delete` keeps its id. App's messages become `route M = POST "/_/<M>"` in App.
14. **Cross-module references after migration read `Todos.Index.Index {}`.** A migrated module keeps its name, and its route takes the module's last segment, so the spec's resolution rule gives the doubled name. `login = Auth.Login` becomes `login = Auth.Login.Login`. This plan does not add a shorthand; see the hand-over question.
15. **Test answers.** `Answer` gains `Rendered Route` and `Refreshed`; `Rerendered` stays until PR 9 (the migration rewrites it to `Refreshed`). The spec's `answer.url` and `answer.status` become fields of every step's result record: `{ answer, session, doc, url: Text, status: Int }`. Existing `r.answer == …` tests keep compiling.
16. **`alder routes --json`** gains `method`. `kind` stays `"page"` for GET and `"msg"` for other methods until PR 9, so older editor plugins keep working; PR 9 sets `kind` to `"route"`.
17. **`alder fmt` aligns route lines** in columns: name, method, path, `{ params }` with ` form F` when present, then `requires …`. Route lines are never wrapped.
18. **`new page` stays as an alias** of `new route` (printing "`alder new page` is now `alder new route`") until PR 9; `new msg` becomes an alias of `new route --method POST`.

## Review Focus

- **A forged `Alder-Page` or `Referer`** (`//evil.example/x`, `https://evil.example/`, `/\evil`, a 9 KB header): a `refresh` answers 303 to a same-origin path only, or `/`. Never another host. Test in Task 1.4.
- **`render r` whose `r.load` fails** (the row was deleted meanwhile; a `requires` redirect; a 500): no patch, so the `<li>` is not replaced by the not-found page. A 404 sends an error toast `Not found`; a redirect navigates; a 500 logs and sends the error toast. Test in Task 1.4.
- **`_method` abuse:** `_method=GET`, `_method=post`, `_method` on a PATCH request, two `_method` values. Only one value of `PUT`, `PATCH` or `DELETE` on a POST is honoured; any other `_method` on a POST is `400`, and it is ignored on other methods. Test in Task 1.2.
- **A `render` whose root id is not on the held page** (the row was filtered out): a real browser drops it silently; a test fails the step naming the id, so the bug shows in `alder test`. Test in Task 4.2.
- **Comments survive the migration**, including comments between `update` arms, above `msg` lines and inside tests. Test in Task 7.1.
