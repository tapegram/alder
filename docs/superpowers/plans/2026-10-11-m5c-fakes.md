# M5c: Stateful fakes (`fake` and `Test.fake`) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A test can replace a whole capability with an in-memory implementation written in Alder — every entry, with tables of its own in the per-test database — and drive a lifecycle through it (`let _ <- Test.fake Stripe`, then charge, refund, and read the fake's table back). Fakes exist only in test builds; production binaries contain no fake code and no fake tables.

**Architecture:** (1) Language: a `fake X { tables; entries }` declaration beside capability `X`, resolved, checked against the capability's entry types, lowered to `ir.Program.Fakes` (its tables kept OUT of `Program.Tables`), and a `Test.fake` special form. (2) Runtime and codegen: `eff.RunInner` runs under the current effect kind; `db.CreateTables` creates test-only tables after the app's schema is in place; `rtesting.Options.TestTables`; gen emits, only with `Options{Tests: true}`, a Go struct per fake implementing the capability's interface by running the Alder entries through `RunInner`, `FakeTables`, and `Test.fake`'s Call that swaps `env.Caps[key]`. (3) The blog gains a Markdown fake and a test using it; chapter 10 teaches fakes; a Stripe-shaped fake lives in the gen e2e fixture and the book.

**Tech Stack:** Go; the existing `Test.run` machinery (`rtesting.Inner`, `TestRun` emission) is the model.

**Spec:** `docs/superpowers/specs/2026-10-10-m5-blog-migrations-fakes-design.md` — "Stateful fakes (`fake` and `Test.fake`)" including "The test schema (recorded by the M5b final-review wave)", "Error handling", "Testing". Read it first; the test-schema paragraph is binding.

## Global Constraints

- Production builds (`alder build`, `alder run`, eval's mains) contain no fake symbols, no fake tables, no `FakeTables` var with entries; a golden proves it. Test builds (`alder test`) contain them; a gen e2e test runs a fake.
- `Program.Tables`, `migrate.FromProgram`, E0019, `schema.json` and every migration never see a fake's tables (they are created by `db.CreateTables` after `Migrate`/`Ensure`, never before; `Migrate` is never run after `CreateTables` on the same store).
- Gate: `gofmt -l $(git ls-files '*.go')` empty; `go vet ./...`; `go test ./... -count=1`; both examples check/build/test (todos 3; blog grows); `(cd experiments && python3 -m unittest)`; `go test ./book -count=1`.
- Every new diagnostic (E0020, E0021) has a corpus case and an `alder explain` text; chapter 10 states the rules with verified blocks; chapter 11's codes table.
- No defaulted record literals (unchanged); a fake's table follows the same rules as an app table except placement (E0018 exempt) and the test-only rule (E0021).

## Review Focus

1. **A fake entry that fails** (`Task.fail "card declined"`): expected — under `Test.run` it is `Err "card declined"` with the fake's own trace steps inside the window; outside `Test.run` the test fails with that message; the fake's table writes before the failure are rolled back with the savepoint. Test in Task 2 (gen e2e) and Task 3 (the book's Stripe example as a test).
2. **A fake's table referenced from app code** (`Db.from Payments.Charge` in a page): expected — E0021 at the use, naming the fake; from a test or from the fake's own entries it is fine. Test in Task 1 (corpus).
3. **`Test.fake X` where `X` has no `fake`**, or `Test.fake` outside a `test`, or a fake missing an entry / with an extra one: expected — one clear error each. Test in Task 1 (corpus ×4).
4. **A fake installed, then the real adapter is also present** (the blog: `Markdown` has an adapter AND a fake): expected — the test that installs the fake uses the fake; a test that does not install it uses the real adapter; the trace shows `Test.fake Markdown` then `Markdown.render`. Test in Task 3 (the blog's two tests).
5. **A fake's table that `@ref`s an app table** (`Charge.user @ref User`): expected — created after the app's tables, with its index; a `@cascade` from the app table to the fake's table is impossible (an app table never refers to a fake's). Test in Task 2 (`db.CreateTables` with a ref) and Task 1 (the checker rejects `@ref` from an app table to a fake's table: E0021).

**Interfaces (binding for Task 2):**
```go
// ir
type Fake struct {
    Module     string
    Capability *Capability   // the capability it implements (same module)
    Tables     []*Table      // test-only; not in Program.Tables
    Entries    []*Value      // one per Capability.Entries[i], same order; Value.Name = entry name; Value.Type = entry type
}
type TestFake struct { Typed; Fake *Fake }   // type Task Unit
// Program.Fakes []*Fake  (module order)
```
`names`: a fake's tables are ordinary module tables for scoping (`Payments.Charge`); `Test.fake Stripe` resolves `Stripe` to `RefCapability{Module: "Payments", Name: "Payments.Stripe"}` (same shape as a capability call's head).
