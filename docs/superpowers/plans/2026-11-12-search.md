# Search by name or by type — Implementation Plan (alder repo)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a search engine over the standard library and the app's declarations, by name or by type, with an `alder search` command and language-server requests that the editor plugins will use.

**Architecture:** A new package `internal/search` builds an index from a checked program and answers text queries; it never touches the build's substitution after the index is built. `cmd/alder/search.go` and `internal/lsp/search.go` are thin front doors that shape the same hits as file/line or URI/range, the way `alder routes` and `alder/routes` share `buildkit.Routes`. The language server also computes the edit for a picked result, so plugins never build text.

**Tech Stack:** Go (standard library only), the existing `internal/types` unifier, `internal/syntax` parser, `internal/check`, `internal/names`, `internal/lsp`.

**Spec:** `docs/superpowers/specs/2026-11-12-search-design.md` (issue tapegram/alder#166). Read it before any task; every task argues from it.

**Facts:** `docs/superpowers/plans/2026-11-12-search-facts.md` holds the exact existing signatures this plan names (sections A–G). Read the sections your task lists.

**Scope:** the spec's PR 1 (Tasks 1–6) and PR 2 (Tasks 7–10). The alder.nvim and alder-vscode pickers (the spec's PRs 3 and 4) get their own plan after this one lands.

## Global Constraints

- No new Go dependencies. The fuzzy scorer is hand-written.
- Nothing changes in what source files accept. `_` in a type is legal only through `syntax.ParseType(src, true)`.
- Search must work on a build with typed holes (`res.Holes > 0`) and must never call `ir.Lower` or `buildkit.Routes`.
- Doc text comes from `syntax.DocOf(mod.Lines, decl.GetSpan().Start.Line)` and nowhere else.
- Default result cap: 50. Budget: under 50 ms a query for the stdlib plus 2,000 app declarations.
- `source` is a free string (`"stdlib"`, `"app"`); no code may branch on "not stdlib means app" except the tie-break in ranking, which orders `app` first, `stdlib` second, anything else after.
- A query never makes a request fail. Bad query text gives an empty result and a note; the only error exits are the CLI's usage error and unparsable type query (exit 2).
- Two PRs, each from a short branch off `main`: `search-engine` (Tasks 1–6), then `search-lsp` (Tasks 7–10). One commit per task or more. Merge each PR when CI is green; do not start the second branch before the first is merged.
- Before every commit: `gofmt -l $(git ls-files '*.go')` prints nothing and `go vet ./...` passes. Before each PR: `scripts/test.sh -short` passes.
- **Working hours:** no agent or background work 09:00–17:00 America/New_York Monday to Friday. Check with `TZ=America/New_York date '+%u %H:%M'` before starting a task.
- **Models** (subagent-driven execution): Sonnet for Tasks 1, 2, 3, 6, 9, 10; Opus for Tasks 4, 5, 7, 8 and for each PR's whole-branch review.
- Book prose follows `docs/markdown-style.md`: wrap near 80 columns, never rename or remove a heading.

Rules the tests pin:

- The base unifier is `res.U.Clone()` with `Subst` replaced by an empty `types.Subst{}`. It keeps the registered tables and the variable counter.

### Task 3: `Search` and name search

**Files:**
- Create: `internal/search/search.go`, `internal/search/name.go`
- Test: `internal/search/name_test.go`

**Interfaces:**
- Consumes: `Index`, `Entry` (Task 2).
- Produces:

```go
type Options struct {
	Limit  int    // 0 means 50; negative means no limit
	Source string // "" for every source, else only entries with this Source
}

type Hit struct {
	Entry     *Entry
	Match     string // "", or for type queries "exact", "general" or "reordered"
	Args      int    // produces mode: leading arguments still to supply
}

type Response struct {
	Query   string
	Mode    string // "name", "type" or "produces"
	Note    string
	Bad     bool   // a type query that does not parse
	Results []Hit  // never nil
}

func (ix *Index) Search(query string, o Options) Response
```

Mode: after trimming, a query that starts with `:` is `produces`; otherwise one that contains `->` is `type`; otherwise `name`. An empty query is `name` with no results. In this task `type` and `produces` return no results; Tasks 4 and 5 fill them in.

Name search, on the trimmed query, case-insensitive:

- With a `.`: split at the last one into a module part and a name part. An entry's module matches when it equals the module part, or ends with `"." + part`. If no entry matches that way, a module matches when its last segment starts with the part. Within the matching modules: an empty name part lists every entry in index order; otherwise rank by the tiers below.
- Without a `.`, an entry's tier is the first that applies:
  0. the name equals the query;
  1. the name starts with it;
  2. it occurs in the name at a word boundary (the start of a camelCase hump);
  3. it occurs in the name elsewhere;
  4. it is a subsequence of the name;
  5. it is a subsequence of `Module.name`.
- Order: tier, then shorter name, then source (`app`, `stdlib`, others), then `Module.name`.

**Files:**

- Produces:

```go
// In internal/check: apply a declared type to arguments, as typeOf does for a TypeName.
// ok is false when the number of arguments is wrong.
func ApplyTypeArgs(decl types.Type, args []types.Type) (t types.Type, ok bool)

// In internal/search (unexported): the query's type, on a fresh clone of the base unifier.
// note is set, and t is nil, when a name is unknown or ambiguous.
// bad is true when the text does not parse as a type.
func (ix *Index) queryType(src string) (t types.Type, u *types.Unifier, note string, bad bool)
```

`ApplyTypeArgs` wraps the unexported `applyArgs` and arity check that `typeOf` uses (`internal/check/decls.go`, about :245). If they need checker state a caller outside the package cannot supply, copy the logic into `internal/search/query.go` instead and say so in the commit message.

Conversion rules:

- `*syntax.TypeVar` named `_` → `u.Fresh()`: every `_` is its own variable.
- Any other `*syntax.TypeVar` → `&types.Param{Name}`: rigid.
- `*syntax.FunType` → `*types.Fun`; `*syntax.RecordType` → an anonymous `*types.Record`.
- `*syntax.TypeName` → resolve the declaration, convert the arguments, `ApplyTypeArgs`. A wrong number of arguments is a note: ``"`List` takes 1 type argument"`` (the name and the count).
- Resolution, against the index's declared types (keys `"Module.Type"`, split at the last dot):
  1. unqualified, and `"Prelude." + Name` exists → that;
  2. qualified → the declarations named `Name` whose module equals the qualifier or ends with `"." + qualifier`;
  3. unqualified otherwise → every declaration named `Name`;
  4. exactly one candidate → it. None → note ``"no type named `X`"`` (as typed, with its qualifier). Several → note ``"`X` is ambiguous: A.X, B.X"``, choices sorted.
- A parse failure → `bad` true, note `"not a complete type"`.

In `Search`: for `type`, the query text is the whole query; for `produces`, the text after the `:`. When `queryType` gives a note or `bad`, `Search` returns it with no results. Also add the hint: a `name` query with zero hits, for which `queryType(query)` succeeds, gets the note ``"to search by type, start with `:`"``.

### Task 5: type matching, ranking, the golden queries and the budget

**Files:**
- Create: `internal/search/match.go`
- Test: `internal/search/match_test.go`, `internal/search/golden_test.go`, `internal/search/bench_test.go`
- Modify: `docs/superpowers/specs/2026-11-12-search-design.md` only if a golden row has to change (see Step 6)

**Facts:** section A, the notes on `Check`, `Instantiate` and mutation.

**Interfaces:**
- Consumes: `queryType` (Task 4), `Hit` (Task 3).
- Produces: `type` and `produces` results from `Search`, with `Hit.Match` and `Hit.Args` set.

The matching rule is the spec's: a candidate matches when it could be used where the query's type is expected, which is `u.Check(u.Instantiate(candidate), queryType) == nil`.

Mechanics that the signature does not determine:

- `Check` mutates its unifier and does not roll back. Every attempt runs on its own `Clone()` of the query's unifier (which holds only the wildcards, so a clone is cheap). Never clone `res.U`.
- **`type` mode.** Only `Function` and `Constructor` entries whose type is a `*types.Fun` with the query's number of parameters. Try the declared order first. If that fails and the function has 2 to 4 parameters, try the other permutations of the candidate's instantiated parameters, in a fixed order, stopping at the first that matches: that hit is `reordered`. When the query is not a function type at the top level (`List (a -> b)`), only entries that are not functions are tried, with a direct check.
- **`produces` mode.** No reordering. Let the query have m parameters (0 when it is not a function type). A candidate that is not a function matches by a direct check, `Args` 0. A function with n ≥ m parameters matches when the function made of its last m parameters and its result (just the result when m is 0) checks against the query; `Args` is n − m. Only that split is tried: a function whose bare-variable result could itself stand for a function (`Maybe.withDefault` for `: Int -> Text`) is not offered.
- `TypeDecl` entries never match a type query.
- **Bound count:** after a successful check, the number of the candidate's own instantiated variables that `Apply` resolves to something other than a `*types.Var` or a `*types.Param`.
- `Match` is `reordered` for a permuted hit, else `exact` when the bound count is 0, else `general`.
- **Bare result:** the candidate's declared result (its type, for a non-function) is a `*types.Param`.
- **Order**, most significant first: bare result last (`produces` only); lower bound count; lower `Args` (`produces` only); not reordered before reordered; source (`app`, `stdlib`, others); `Module.name`.

Behaviour:

- The entry is the index entry with that module, name and kind; none → `codeInvalidParams`.
- **Where:** if the position is on a typed hole of the last good build (`holeAt`), the edit replaces the hole's span. Otherwise it inserts at the position.
- **The name written:**
  - module `Prelude`, or the file's own module → the bare name;
  - a stdlib module, or an app module the file imports → `Q.name`, with `Q` from `a.prog.Qualify(m.Name)`;
  - an app module the file does not import → `Q.name` with the qualifier `importClause` would give it, plus a second edit that inserts `import <importClause>` on a new line after the file's last import (after the `module` line, separated by one blank line, when it has none). The result must be stable under the formatter.
- **Arguments:** only when replacing a hole and `Args > 0`: the name is followed by `Args` new holes, `?a`, `?b`, `?c`, … in order, skipping any name already used by a hole in the file. The whole expression is wrapped in parentheses when the hole is the `Fn` or one of the `Args` of a `*syntax.App` (find the parent with `syntax.NodeAt`).
- The result is a `workspaceEdit` with one `textDocumentEdit`: the document's version when it is open, edits in wire units computed against the current text.
